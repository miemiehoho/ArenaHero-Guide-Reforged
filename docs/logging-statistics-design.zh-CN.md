# ArenaHero 中文日志统计增强详细设计

> 设计日期：2026-08-16
> 适用分支：`进攻才是最好的防守`
> 依赖日志体系：`docs/logging-system-design.zh-CN.md`
> 状态：设计阶段

## 1. 背景与目标

当前 Agent 已在每个实际规划 Tick 写入中文 `统计` JSONL 记录，记录了 `Worker数`、
`Vanguard数`、`Ranger数`、`人口`、`资源`、`容量`、动作、事件和规划指标。但现有
`arena_log.py stats` 只汇总事件、动作、资源起止值和规划耗时，无法直接回答：

- 一个 Tick 区间内各种兵种的起点、终点、峰值和平均数量是多少；
- 人口增长与三种 Unit 数量是否一致；
- Core 资源和容量的最低、最高、平均值，以及资源占用率是否长期饱和；
- 区间内各类官方事件发生了多少次，哪些事件类别占主导；
- 查询区间最后一个 Tick 的兵种、人口、资源和容量快照是什么。

本阶段增强离线统计查询，不改变 Agent 决策、提交、状态持久化或官方协议。

## 2. 官方事实与数据边界

官方状态模型规定：

- `population` 只计算存活 Unit，Core 不计入人口；Unit 类型为 `WORKER`、`VANGUARD`、
  `RANGER`；
- `resources` 是当前 Core 资源，容量按当前人口计算，官方规则为
  `max(10, population * 5)`；人口下降时超额资源可能立即销毁；
- `state.events` 是上一 Tick 结算解释，当前完整状态是数量和资源的权威来源；不能用
  `SPAWN` 动作或事件摘要推断当前存活兵力；
- 日志中的官方 `event_type`、`reason_code` 必须保持原文，未知值不能被猜测翻译。

因此统计只读取 `类别=统计` 的快照和独立 `类别=事件` 记录，不另开 SDK 事件流，也不连接
真实服务端。统计输出是诊断结果，不写回 `.arena_core_state.json`。

## 3. 聚合输出契约

`aggregate_stats(records, from_tick=None, to_tick=None)` 保留现有字段，并增加以下中文键：

```json
{
  "兵种数量": {
    "Worker": {"样本数": 2, "起点": 4, "终点": 4, "最小": 4, "最大": 4, "平均": 4.0},
    "Vanguard": {"样本数": 2, "起点": 10, "终点": 11, "最小": 10, "最大": 11, "平均": 10.5},
    "Ranger": {"样本数": 2, "起点": 5, "终点": 5, "最小": 5, "最大": 5, "平均": 5.0}
  },
  "人口统计": {"样本数": 2, "起点": 19, "终点": 20, "最小": 19, "最大": 20, "平均": 19.5},
  "资源统计": {
    "资源": {"样本数": 2, "起点": 80, "终点": 90, "最小": 80, "最大": 90, "平均": 85.0},
    "容量": {"样本数": 2, "起点": 95, "终点": 100, "最小": 95, "最大": 100, "平均": 97.5},
    "资源占用率": {"样本数": 2, "起点": 0.842, "终点": 0.9, "最小": 0.842, "最大": 0.9, "平均": 0.871}
  },
  "最新快照": {"Tick": 10583, "Worker数": 4, "Vanguard数": 11, "Ranger数": 5, "人口": 20},
  "事件类别数量": {"Worker 经济事件": 12, "战斗事件": 3}
}
```

### 3.1 数值摘要

所有摘要统一返回 `样本数`、`起点`、`终点`、`最小`、`最大`、`平均`：

- 先按 Tick 区间筛选统计记录，再按 Tick 升序计算起点和终点；重复 Tick 不隐式去重；
- 只接受整数或浮点数，不接受布尔值、字符串和 `null`；缺字段不计入样本；
- 无样本时 `样本数=0`，其余字段为 `null`，不把未知数据伪造为 0；
- 平均值和资源占用率保留 3 位小数；整数数量仍以 JSON 数字输出。

### 3.2 兵种和人口

兵种摘要分别读取 `Worker数`、`Vanguard数`、`Ranger数`，输出键名固定为 `Worker`、
`Vanguard`、`Ranger`。人口摘要读取官方快照字段 `人口`。三种兵种数量的和用于诊断人口
一致性，但不在聚合器中强行修正或覆盖官方 `人口`。

### 3.3 资源和容量

`资源统计.资源` 读取 `资源`，`资源统计.容量` 读取 `容量`。`资源统计.资源占用率` 按
`资源 / 容量` 逐样本计算，仅当容量为正数时纳入；容量为 0 或缺失的样本跳过。现有顶层
`资源起点`、`资源终点`、`资源变化` 保留，兼容已有脚本。

### 3.4 最新快照与事件类别

`最新快照` 选择区间内最大 Tick 的最后一条 `统计` 记录，保留 Tick、兵种数量、人口、资源
和容量字段。事件总数仍只来自独立事件记录，避免与 Tick 统计里的 `事件数量`摘要重复；新增
`事件类别数量` 使用既有 `event_category()`，未知事件归入 `官方事件`。

## 4. CLI 设计

不增加新的并行命令，继续增强 `stats`：

```bash
# 查看完整中文摘要
python arena_log.py stats --from-tick 10000 --to-tick 10583

# 输出给脚本、PowerShell 或 jq 使用
python arena_log.py stats --from-tick 10000 --to-tick 10583 --json

# 查询已部署实例的日志目录
python arena_log.py --log-dir /path/to/WorkingDirectory stats --json
```

文本模式按中文键逐行输出；`--json` 输出完整嵌套对象。旧日志没有新字段时仍输出现有事件、
动作、资源和规划统计，新字段用空摘要表示。

## 5. 实现边界与兼容性

只修改 `arena_log.py`、`test_arena_log.py` 和本项目中文文档：

- 不修改官方三个项目、Python SDK、`arena_core_agent.py` 的计划行为或日志轮转配置；
- 不改动 `.arena_core_state.json`、`.env` 和已有 JSONL 内容；
- 读取仍然按轮转文件从旧到新合并，坏行继续跳过并输出中文警告；
- 聚合不保存跨进程缓存，命令执行结束即释放内存；
- 既有顶层字段和既有事件去重语义保持不变。

## 6. 测试与验收

新增或扩展 `test_arena_log.py`，至少覆盖：

1. 两个完整 Tick 得到兵种、人口、资源、容量和占用率的起点/终点/最小/最大/平均；
2. 缺少 `Ranger数`、容量为 `null` 或 0 时不产生伪造 0，不发生除零；
3. `from_tick`/`to_tick` 只影响区间，最新快照取区间最大 Tick；
4. 官方前缀事件被正确分类，未知事件归入 `官方事件`；
5. `stats --json` 包含新增中文键，空日志仍返回成功码；
6. 既有 132 个 Agent/日志测试、`compileall`、`git diff --check` 和本地 Markdown 链接检查通过。
